# Visual regression prompts

Use these prompts when checking that the visual decision layer is actually being followed:

1. A dense B2B workbench with no existing brand system. Require a Visual Context Profile, at least two materially different directions when a real trade-off exists, one selected grammar contract and a realistic stress test.
2. A mobile consumer experience with an existing Material foundation. Require the agent to preserve interaction primitives while choosing a separate brand direction and explaining which Material defaults it rejects.
3. A multi-page product after a shared token change. Require an art-direction consistency review, an anti-template review and regression checks across all impacted pages.
4. A requested glassmorphism redesign of a data-heavy table. Require the agent to evaluate the task and accessibility risks, constrain translucency to appropriate layers or reject it, and explain the repair.
5. A page with long labels, missing values, errors, permissions and narrow width. Require visual review of all states, not only the happy path.
6. A three-pane editor with optional inspector, reference preview, command bar and assistant. Require space roles, layout alternative comparison, V0–V4 lifecycle, pin/remember policy, collapse prohibitions, responsive transformation and floating occlusion budget.
7. A “simple” settings page with collapsible sections and validation errors. Require every section to have a visibility and state-restoration decision, and require the agent to mark any non-applicable field explicitly instead of skipping it.
8. A dense table with sticky header/first column, long CJK labels, virtualized rows and a drawer. Require the UI Engineering Blueprint to cover intrinsic sizing, scroll ownership, stacking order, sticky offsets, focus visibility, virtualization measurement and screenshot/runtime checks.
9. A mobile chat composer with safe area, keyboard, streaming content and a floating assistant. Require dynamic viewport, keyboard-aware layout, stable async sizing, overlay collision and touch/keyboard checks.

Pass condition: the response shows the visual context, rationale, contract, component derivation, spatial roles, lifecycle/persistence table, Engineering Blueprint, responsive and occlusion decisions, stress cases and review findings. A palette or component list alone is insufficient; a screenshot alone is not proof of browser-level correctness.
