# Visibility and Persistence

## 1. 可见性等级

每个区域和浮层选择一个默认等级，并说明从一个等级进入另一个等级的触发器：

| 等级 | 名称 | 行为 | 适用 |
| --- | --- | --- | --- |
| V0 | Persistent | 始终可见，占用稳定空间 | 主任务、关键状态、稳定导航 |
| V1 | Expanded / Collapsible | 默认展开，可收缩并保留入口 | 高频参考、检查器、过滤器 |
| V2 | Collapsed Available | 默认收缩，有明确可见入口 | 中频工具、次要参考 |
| V3 | On Demand | 触发后打开，关闭后回到原上下文 | 低频设置、局部解释、复杂筛选 |
| V4 | Transient | 短暂显示并按规则消失 | Toast、Tooltip、临时进度 |

## 2. 影响生命周期的因素

逐项判断：任务频率、任务关键性、上下文依赖、信息半衰期、重新打开成本、占用空间、遮挡风险、权限和错误恢复成本。不要从“设计惯例”直接推断默认可见性。

### 必须保护的状态

不得在以下状态中自动收缩、关闭或切换上下文：未保存输入、当前键盘焦点、活动错误、任务关键结果、用户正在比较的对象、进行中的上传/计算、用户明确固定的面板。用户 pin 和记忆偏好优先于自动策略，除非会造成不可操作、不安全或严重遮挡。

### 自动收缩规则

- 仅在用户完成安全边界、离开上下文或空间压力达到预设阈值时收缩。
- 收缩后必须保留可见入口、当前选择摘要、未读状态或错误标记。
- 反复重新打开同一面板是持久化不足的信号；记录为修复候选。
- 自动关闭的浮层必须有明确的 dismiss 规则、Escape 行为和焦点返回目标。

## 3. 状态恢复

对每个可隐藏区域记录是否恢复：展开状态、面板宽度、滚动位置、选中项、过滤器、排序、草稿、未读状态和最近触发源。恢复失败时提供可理解的默认值，并避免让用户重新执行已完成的关键步骤。

## 4. 一个可选的工程启发式

如果团队需要快速排序，可用 `L = 3F + 3C + 2R + 2X - 2S - 2O` 作为讨论线索：`F` 频率、`C` 关键性、`R` 参考依赖、`X` 恢复成本、`S` 空间成本、`O` 遮挡成本，每项 0–3。它不是通用真理、不可替代用户研究，也不得作为跳过字段的理由。高 `L` 倾向 V0/V1，中等倾向 V1/V2，低倾向 V3/V4；最终仍需结合响应式和无障碍检查。
