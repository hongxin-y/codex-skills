# Task-to-layout selection

Choose layouts according to the dominant job, information density, object relationships and continuity needs.

| Pattern | Good fit | Common failure |
| --- | --- | --- |
| Queue / inbox | Triage and resolve incoming work | Opening every item as an unrelated page |
| Table workbench | Repeated filtering, inspection and bulk work | Wide unreadable tables |
| Master-detail | Process many records while retaining list context | Detail area too narrow |
| Search + results | Locate, narrow and evaluate objects | Losing query and filters |
| Dashboard | Monitor health, trends and exceptions | Replacing task tools with KPI cards |
| Form workspace | Enter or edit structured information | Fragmenting a simple form |
| Wizard | Staged dependencies and consequential decisions | Unnecessary steps |
| Timeline / calendar | Sequence and time are central | Forcing unrelated data into a calendar |
| Canvas / editor | Compose, arrange or manipulate content | Unfocused tool overload |
| Feed / discovery | Browse and explore changing content | Hiding deliberate search |
| Split comparison | Evaluate alternatives side by side | No clear differentiation |
| Detail page | Deep review, complex editing or shareable context | Routine navigation overhead |

## Selection procedure

Identify whether users process many objects repeatedly or one object deeply. Determine whether comparison, time, spatial editing, discovery or dependency dominates. Compare plausible patterns before choosing.

A hybrid is valid when the hierarchy remains clear.

## Multi-page rule

Choose page boundaries only after assigning jobs and responsibilities. A page exists because a distinct task context, permission boundary, shareable state or information depth justifies it—not because a navigation menu needs more entries.

Use [multi-page-design](multi-page-design.md) to document page ownership before building screens.

## Responsive transformation

Desktop may support list and detail simultaneously. Mobile may use focused sequential views while preserving search, selection, return position and drafts. Do not merely squeeze a desktop table into a narrow screen.
