# Anti-AI-template review

## Purpose

“AI look” is not a formal visual score. Treat it as a diagnostic for high-probability visual choices that lack a business or product reason. Separate findings into:

- USABILITY DEFECT: harms finding, reading, operating or recovering.
- SYSTEM INCONSISTENCY: conflicts with shared semantics or contracts.
- ART-DIRECTION WEAKNESS: lacks a coherent visual thesis or grammar.
- SUBJECTIVE TASTE: preference without a demonstrable task or system impact.

Do not present subjective taste as an accessibility or usability fact.

## Issue patterns

| Symptom | Likely cause | Repair |
| --- | --- | --- |
| White background, purple-blue gradient and glass cards | No art direction; generic tech prior | Compare directions and give every effect a role |
| Every piece of content is a card | No content relationship model | Use list/table/sections for homogeneous content; reserve cards for real grouping or entry points |
| Every element has a large radius | No shape grammar | Define a radius family and semantic exceptions |
| All metadata is a pill | Containers replace hierarchy | Use text and alignment; reserve pills for bounded status, tags and filters |
| Every homepage has a centered hero | Marketing template prior | Choose composition from content, brand and conversion intent |
| Every backend has KPI cards | Dashboard assumed by default | Use queue/workbench unless monitoring is the real job |
| Every card has icon, title and description | Component template drives content | Build content inventory first |
| Charts are decorative | No analytical question | State the question each chart answers or remove it |
| Pages look unrelated | No cross-page art contract | Share type, grid, surface, shape, icon and motion grammar |
| All spacing is loose | Premium equated with whitespace | Match density to frequency and scanning |
| Type weights and sizes drift | No type roles | Define semantic type roles and numeric treatment |
| Dark mode glows and neon accents | Cliché dark aesthetic | Rebuild through luminance hierarchy and semantic tokens |
| Placeholder data controls layout | Styling on ideal content | Stress test realistic long, short, error and empty content |
| Every page has an illustration | Decoration fills space | Require orientation, education, emotion or brand purpose |
| Mixed icon families | No icon grammar | Standardize stroke/fill, optical weight and metaphors |
| Only happy path is designed | Screenshot-driven output | Include error, permission, disabled, loading and long-data review |

## Review heuristic

If the design could become an unrelated SaaS by changing only the logo and accent color, the art direction is under-specified. Repair by strengthening the thesis, typography, grid, palette strategy, density, surface/shape grammar, imagery, iconography or motion, not by adding more decoration.

## Required anti-template questions

- Does every gradient, blur, glow, illustration and icon have a task, orientation, evidence or brand reason?
- Are cards used because information is genuinely grouped?
- Are important differences expressed through hierarchy rather than decoration?
- Is content realistic enough to change layout decisions?
- Does the same component keep the same visual semantics across pages?
- Has a trend been used as an effect without adopting its underlying design logic?
