# Perceived Quality and Anti-AI Review

视觉质量不是“更花哨”，也不是一个总分。它是任务适配、可访问性、语义匹配、层级、真实性、连贯性、工艺、克制和辨识度的组合判断。

## 1. 评审维度和优先级

按以下顺序检查，每项写 `Strong / Adequate / Weak / Critical` 及证据：

1. Task fit：是否帮助用户完成当前任务。
2. Accessibility：对比度、焦点、目标尺寸、键盘、读屏和动效是否可用。
3. Semantic fit：颜色、形状、密度、动效和组件是否表达真实语义。
4. Hierarchy：注意力、操作优先级和阅读路径是否清楚。
5. Authenticity：是否有产品和内容特有的选择，而非通用模板。
6. Coherence：跨页面、状态和组件是否遵循同一语法。
7. Craft：间距、对齐、状态、错误和边界是否经过打磨。
8. Restraint：是否删除了不提供价值的装饰、浮层和变化。
9. Distinctiveness：是否形成可识别但不牺牲任务效率的特征。

不要把低辨识度当作必须增加视觉噪声的理由，也不要用审美偏好掩盖任务或可访问性缺陷。

用户心理判断必须参考 [user-perception-and-visual-decisions](user-perception-and-visual-decisions.md)：记录假设、可观察信号、反风险和验证方式，不把颜色或风格关联当成确定因果。

## 2. 反 AI 味三项测试

- **Deletion test**：删除渐变、发光、装饰图形、重复卡片或浮动元素后，任务是否更清楚？若是，删除或说明保留理由。
- **Substitution test**：把品牌名、文案和颜色替换为另一产品后，结构是否几乎不变？若是，补充真实对象、业务状态、内容密度或产品专属语法。
- **Real-content test**：用长标题、空状态、错误、极端数量、混合语言、权限差异和真实状态压力测试。不得只用占位短句验收。

## 3. 证据和推断

把“看起来像 AI 模板”写成可观察症状：高频的圆角卡片、同质化渐变、无语义的玻璃表面、重复的居中标题、装饰性图标、虚构短文案、没有状态差异、所有页面同一布局。不要声称模型天生偏好某种颜色或组件，除非有可核验数据；这里的判断是设计诊断，不是模型心理结论。

## 4. 修复优先级

先修 Task fit、Accessibility 和 Semantic fit，再修 Hierarchy、Authenticity、Coherence、Craft、Restraint，最后才考虑 Distinctiveness。每次修复记录删掉、替换或新增的决策，以及它对应的任务证据。
