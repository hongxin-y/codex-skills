# Responsive Transformation

响应式不是把桌面尺寸等比缩小，而是保持任务语义、状态和恢复路径的结构变换。

## 1. 默认转换顺序

对每个区域明确是否依次经历：

`resize → compact → rail → drawer/sheet → dedicated page`

- **resize**：先缩小空白和可伸缩列，保留操作顺序。
- **compact**：减少标签、间距和次要装饰，保留语义和状态。
- **rail**：将稳定导航或工具压缩为图标/窄栏，提供标签、键盘和可达入口。
- **drawer/sheet**：把需要连续查看的上下文移出主任务空间，保留触发源和返回焦点。
- **dedicated page**：当内容需要独立滚动、深度编辑、分享、恢复或无障碍结构时转为页面。

不要直接隐藏任务关键内容；先尝试重排、折叠、转层和分页。

## 2. 断点不是决定依据

记录触发转换的实际条件：可用宽度、内容最小可读宽度、操作目标尺寸、键盘空间、辅助技术顺序、并列比较需求和遮挡预算。断点只是实现参数，不是设计理由。

## 3. 跨设备必须保持

- 当前对象、选择、筛选、排序、草稿和错误。
- 当前任务阶段、返回路径和焦点语义。
- 关键状态的可见反馈，不能只保留在 hover 或颜色中。
- 对同一动作的 canonical owner，避免移动端和桌面端产生两套含义。

## 4. 转换验收

在窄屏、长标题、长错误、最小字体、键盘操作和屏幕阅读器结构下检查：是否溢出、遮挡、丢失入口、增加不可控滚动、焦点不可见、状态无法恢复或需要重复输入。每个失败都要回到生命周期和容器选择重新决策。
