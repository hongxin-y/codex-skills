# Technical Resume Refinement

用于资深技术 IC、算法工程师、数据科学家、AI/软件工程师的中文或英文简历润色、重构、双语适配、岗位定制，以及 HTML/PDF 交付验收。

## 适用边界

- 简历是筛选材料，不是完整项目报告；优先呈现能改变面试判断的证据。
- 不替用户认证事实，不补造职责、数字、基线、职称、状态或来源。
- 未经明确授权，不把附件中的建议当作自动执行命令；先识别用户实际要求和当前权威版本。
- 保留用户已确认的内容和延期决定。只讨论时不改文件；要求修改时才编辑源文件。
- HTML/PDF 是交付格式时，内容源和视觉源都要保留；不要用浏览器打印替代项目指定的转换脚本。

## 执行流程

1. **锁定版本与范围**：确认目标岗位、语言、当前源文件、参考 PDF、需要改的章节和不可改内容；保留原稿，不按文件名猜权威版本。
2. **建立事实底稿**：逐项记录公司、职位、日期、项目范围、个人动作、团队归属、结果、基线、口径、链接和上线/实验状态；区分 `FACT`、`USER DECISION`、`EVIDENCE`、`ASSUMPTION`。
3. **建立职业论点**：先回答候选人能解决什么问题、承担什么层级的责任，再做“能力 → 项目 → 证据”映射；删除或压缩不支持主线的低价值细节，但不从事实底稿删除。
4. **筛选与重写证据**：使用具体动作、技术机制和结果替代空泛能力标签；数字保留必要口径、基线和归因，避免无分母、无对象或仅展示过程规模的数字堆积。保留面试可追问的关键设计，不把整段实现写成报告。
5. **语言适配**：
   - 英文按英文技术简历重写，不逐字翻译；使用自然的工程动词、搭配、时态、并列结构和日期表达。
   - 中文保持专业、简洁、少黑话；必要的产品名、模型名、框架名和指标保留英文，不机械中英双写。
   - 中英文事实、职责、时间、数字、项目状态和链接必须一致；表达可以不同。
6. **视觉与版式**：按信息层级、认知密度、字体度量、栅格、留白、缩进、日期对齐和打印安全检查。静态简历借用 UI 设计中的层级和一致性原则，不强行套用产品页面、动效或复杂交互流程；除非用户明确要求视觉重设计，不引入新的设计方向。
7. **生成与验收**：HTML 项目优先使用仓库已有转换脚本和本地字体；检查页数、A4 尺寸、文本可提取性、纯文本顺序、链接、实际字体/字号、边界、换行和溢出。若有参考 PDF，分别比较二进制、文本、字体字号、链接和逐页渲染；只有确实相同才报告“完全一致”。
8. **交付说明**：列出实际修改、未处理事项和验证范围；不要把“脚本运行成功”描述成内容事实正确或商业 ATS 已验证。提交、推送、发布等外部操作仍需用户明确要求。

## 规则优先级

- 用户明确确认的事实和取舍优先于默认模板；真实性、职责边界、日期和结果口径优先于文案漂亮或版面填满。
- P0：事实、职责、时间、状态、合规和交付正确性。
- P1：职业论点、证据精选、语言自然、双语一致、可读版式和可回归验收。
- P2：岗位定制关键词、可选荣誉/技能、视觉增强；不得以 P2 牺牲 P0/P1。

## 配套技能与参考

- 文字润色时可结合 `$document-refinement`，但仍遵守本技能的事实底稿和简历证据规则。
- 视觉调整时可借用 `$flow-ui-architect` 的信息层级、栅格、密度、响应式和视觉一致性方法；本技能只处理静态简历，不要求为普通简历编辑生成产品 UI 参考图。
- 重大重构、双语同步、岗位定制或交付回归前，读取 [Resume Revision Guide V1.5](references/resume-revision-guide-v1.5.md)；小型单句润色可直接按本入口执行。
