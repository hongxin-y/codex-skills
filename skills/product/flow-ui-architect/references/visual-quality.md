# Visual quality and coherent art direction

A good UI communicates product identity while supporting the user's real job.

## Visual thesis

Choose an intentional direction grounded in task context, such as calm operational density or warm mobile discovery. Translate it into type, grid, density, palette strategy, shape, surface/depth, imagery, icons, motion and component variants. Use [visual-direction-selection](visual-direction-selection.md) before styling and [component-style-grammar](component-style-grammar.md) before selecting variants.

Avoid a generic collection of unrelated cards, gradients and metrics.

## Generation before polish

Visual quality is not only a final inspection. It must be generated from a Visual Context Profile, compared against meaningful candidate directions, committed to a Visual Grammar Contract and stress-tested with realistic content before implementation is considered complete.

## Hierarchy

Make the current job, current object, decision context and next action recognizable. Use spacing, alignment and typography to create hierarchy.

Dense interfaces can be excellent when users need scanning and comparison. Do not equate quality with maximum whitespace.

## Typography and composition

Use readable type, purposeful semantic roles, grid alignment, consistent line height, aligned numeric data, predictable spacing and meaningful grouping. Read [typography-and-grid](typography-and-grid.md). The number of font sizes should follow hierarchy, not a quota.

## Surfaces and charts

Use borders, elevation, backgrounds and translucency only to clarify structure. Read [surface-shape-depth](surface-shape-depth.md). Add charts when they answer a real question, with labels, units and accessible summaries.

## Motion and content

Use motion for state feedback and spatial continuity. Read [imagery-iconography-motion](imagery-iconography-motion.md). Respect reduced motion. Write specific labels and recovery-oriented error messages.

## Multi-page design language

Pages can differ in density and composition according to their jobs, but should share a recognizable navigation system, semantic tokens, component behaviors and status vocabulary.

Review realistic content volume, long labels, localization, empty/error states and responsive transformations.
