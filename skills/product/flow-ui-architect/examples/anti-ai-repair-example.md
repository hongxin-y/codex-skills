# Anti-template repair example

## Finding

A proposed operations page uses a centered hero, four KPI cards, rounded glass panels, pill badges for every metadata field and a purple-blue gradient. The data table is below the fold and the most frequent action is hidden in a menu.

## Classification

- Usability defect: the queue and primary action are hard to find.
- Art-direction weakness: no visual thesis beyond a generic SaaS aesthetic.
- System inconsistency: every metadata value uses a pill, so status and ordinary text have the same visual meaning.
- Subjective taste: the gradient is not automatically wrong, but no business or brand reason supports it.

## Repair

1. Rebuild the Visual Context Profile around a dense, repeated operations session.
2. Compare Swiss Operational, Humanist Enterprise and Fluent Productivity directions.
3. Select a border-led, low-chroma operational grammar.
4. Replace KPI cards with a task queue unless monitoring is the actual job.
5. Use text/alignment for ordinary metadata and status-specific variants for state.
6. Move the frequent action into the queue or detail panel.
7. Stress-test long names, missing values, error and permission states.
8. Run cross-page visual and route regression checks.

## Verification

The repair is not complete until the primary queue task is visible, the table survives realistic content, the visual grammar is documented and the issue ledger records affected routes and checks.
