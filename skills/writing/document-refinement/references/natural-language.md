# 自然表达与文体

## 先看用途，不套一种口吻

沿用用户的受众、语气和语言。邮件通常先给答复或请求，保留必要礼貌；报告区分发现和解释；方案区分建议、依据和代价；操作说明要保留步骤、检查与异常处理。专业不等于冷硬，简短不等于删掉关键条件。

保留写得好的原句。不要为了显得“经过润色”全面重写，或把简单动词改成抽象名词。用户要求尽量原文时，先找可保留的句子，只改确有歧义、冗余、不通顺或与本次要求冲突的地方。

## 去掉旁白，不删真实流程

判断句子的对象：它是在说明业务、研究、产品或行动本身，还是在讲“编辑正在怎样写这份文档”？通常只有后者需要移出正文。

| 情况 | 处理原则 |
| --- | --- |
| “本轮先补齐已确定部分，剩余内容后续再完善。” | 属于编辑说明；移到回复中。正文保留已确认内容与必要占位符。 |
| “下面我们将从多个维度进行深入分析。” | 若只是铺垫，直接进入分析；若有导航价值，改成简短具体的范围说明。 |
| “本文件仍处于草稿阶段，待进一步对齐后持续完善。” | 状态信息放在已有状态位置；若状态影响使用，保留具体限制，不反复描述编写进度。 |
| “提交申请后，负责人核验资料；资料不全时退回补充。” | 这是实际流程，应保留，不能因出现过程动词而删除。 |
| “尚未取得样本，当前结果不能用于总体推断。” | 这是证据边界，应保留，不改成无条件结论。 |
| “请在周五前确认负责人。” | 若邮件本就用于请求确认，这是必要行动，不是应清除的编辑旁白。 |

“流程”“中间数据”“复核”“记录”“确认”“后续”等词没有天然问题。不要建立禁词黑名单，也不要把关键词命中称为 AI 检测。无法通过措辞判断作者身份；目标是提升可读性，不是保证通过检测器。

## 少空话，多明确关系

优先写清谁做什么、发生什么、依据是什么、还受什么限制。删除没有信息增量的套话、重复总结、宣传形容词和过度对称的排比。避免中文机械照搬英文名词串，也不把英文全部改成生硬被动句。

以下示例只展示表达方式；其中的措施、期限或结果必须由当前材料支持，不能直接套用。

| 原表达 | 可采用的处理 |
| --- | --- |
| “通过对需求进行全面梳理，进一步实现交付效率的有效提升。” | 若只确定行动，写“梳理需求，减少重复确认”；若连因果关系也未验证，只写已知行动，不能凭空补收益。 |
| “该方案具备强大的灵活性和可扩展性。” | 指出实际允许调整的内容或可增加的容量；没有依据时不保留笼统优势。 |
| “总体来看，这一方案无疑是当前最优的选择。” | 写出选择理由和适用条件；没有比较证据时不要写“最优”。 |
| “Following a thoughtful evaluation, this solution offers robust capabilities.” | 直接说明已知能力及适用场景；若没有实际评估，不保留评估历史。 |
| “The following section will elaborate on the proposed timeline.” | 若只是过渡句，直接给时间安排；如果是长文导航，保留必要的导航信息。 |
| “We may extend the review by up to two weeks if the evidence is incomplete.” | 可以保留；不得简化成 “We will extend the review by two weeks.” |

不要为避免“AI 味”制造另一套固定句型，也不要刻意口语化、添加错字或虚构个人经历。自然表达允许有长短变化、必要的过渡和符合作者习惯的措辞，不以最短字数作为唯一目标。

## 风格修改前后的语义核对

逐项检查本次涉及的内容，而不是给每篇短文强制加表：

- **主体和对象**：谁负责、谁受影响、处理什么，有没有被省略或替换。
- **情态和状态**：可以／应当／必须，建议／计划／已完成，预计／实测，评审／批准，有没有被混用。
- **逻辑关系**：否定、因果、并列、择一、全部／部分、仅限／包括、前提和例外是否保留。
- **数字与时间**：数值、单位、区间、分母、起算点、截止时间和上限是否保留；一个月不自动等于 30 天。
- **证据强度**：观察到、推测、预计、有待验证、有条件成立，是否被改成保证。
- **技术与引用**：专有名词、字段、枚举、公式、代码、引文和链接是否准确；不能把引文润色后继续标成原话。

若变化触及上述含义，就不是单纯润色。回到原意，或把建议作为实质修改单独交给用户选择。不要用“为了更专业”掩盖新增承诺。
